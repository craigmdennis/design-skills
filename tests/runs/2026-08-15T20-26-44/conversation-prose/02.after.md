**3 migrated, tests failing.** All three fail the same way: the handlers still call `req.body`, which does not exist on a Hono context. Hono does not populate a body property. You have to await it, `await c.req.json()` for JSON or `await c.req.parseBody()` for form data. So it is one mechanical fix repeated three times, plus making each handler async if it is not already. I have not applied it yet.

**2 not started, and these are the real problem.** Both use multer for multipart file uploads. The project's dependencies contain no Hono equivalent. Options:

1. Add a dependency — `@hono/node-server` has some helpers — or use `c.req.parseBody()` directly, which handles multipart and returns `File` objects. That may be enough depending on what those routes do with the uploads (disk storage vs. streaming vs. size limits).
2. Keep those two routes on Express behind a mount, if a hybrid is acceptable in this migration.

Which of the two do you want? `parseBody` buffers the whole file in memory, so option 1 is the wrong answer if these routes accept large uploads.
