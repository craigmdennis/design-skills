**3 migrated, tests failing.** All three fail the same way: the handlers still call `req.body`, which doesn't exist on a Hono context. Hono doesn't populate a body property — you have to await it, `await c.req.json()` for JSON or `await c.req.parseBody()` for form data. So it's one mechanical fix repeated three times, plus making each handler async if it isn't already. I haven't applied it yet.

**2 not started, and these are the real problem.** Both use multer for multipart file uploads. There's no Hono equivalent in the project's dependencies. Options as I see them:

1. Add a dependency — `@hono/node-server` has some helpers, or use `c.req.parseBody()` directly, which handles multipart and gives you `File` objects. That may be enough depending on what those routes do with the uploads (disk storage vs. streaming vs. size limits).
2. Keep those two routes on Express behind a mount, if the migration allows a hybrid.

I'd want to know which before I pick. `parseBody` buffers the whole file in memory, so if these routes accept large uploads that's the wrong answer.
