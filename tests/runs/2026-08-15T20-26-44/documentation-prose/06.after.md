# Contributing

Contributions are welcome. This guide covers everything needed to get a change merged.

## Getting started

1. Fork the repository.
2. Make the changes on a branch in the fork.
3. Open a pull request against `main`.

## Commit messages

Commits follow the [Conventional Commits](https://www.conventionalcommits.org/) specification. For example:

```
feat: add retry handling to the upload queue
fix: correct off-by-one in pagination offset
docs: clarify installation steps
```

## Tests

Run the test suite with:

```sh
npm test
```

Every new behaviour requires a test covering it.

## Review and CI

A pull request requires the following before it is merged:

- **One approving review**, and
- **A passing CI run.**

**Exception:** documentation-only changes do not require an approving review. CI must still pass.
