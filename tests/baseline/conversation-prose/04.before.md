The query is the problem worth fixing first: `id` comes straight from the URL and gets concatenated into SQL, so a request for `/users/1 OR 1=1` returns whatever the driver hands back for a multi-row result, and anything nastier depends only on whether your driver allows stacked statements. Parameterise it, and reject non-integer ids at the boundary rather than trusting the query to be safe on its own.

Second, the missing-row path returns `undefined` because the `if` has no `else`. Every other function in the file returns `null`, so any caller written against that convention — `if (user === null)`, or a switch on `null` in a serialiser — will silently take the wrong branch. Make the fallthrough explicit.

```js
function getUser(id) {
  const userId = Number(id);
  if (!Number.isInteger(userId)) return null;

  const row = db.query("SELECT id, email, is_admin FROM users WHERE id = ?", [userId]);
  if (!row) return null;

  return { id: row.id, email: row.email, admin: row.is_admin === 1 };
}
```

Two smaller things folded into that. `SELECT *` drags back every column — password hash included — for three fields you actually use, so name them. And `== 1` papers over not knowing what the driver returns for a boolean column; once you know, `=== 1` or `Boolean(...)` says it plainly.
