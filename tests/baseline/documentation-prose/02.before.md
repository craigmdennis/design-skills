Here is the runbook. Note one omission: the rule about Friday deploys is kept, but the name and date behind it are not — that history is in version control, and repeating it dates the document the moment ownership changes.

```markdown
# Deploy runbook

## Scope

This runbook covers production deploys. Deploys run from the `main` branch only.

## Prerequisites

- The current branch is `main`.
- `SENTRY_AUTH_TOKEN` is set in the environment. The build step requires it.
- The current time is not after 15:00 UTC on a Friday. No deploy happens in that
  window.

## Procedure

1. Run `npm run build`.
2. Check the build output. It must be under 4 MB. Stop here if it is larger.
3. Run `wrangler deploy --env production`.
4. Request `/healthz`. It must return 200 within 60 seconds.

The deploy is complete when `/healthz` returns 200.

## When the health check fails

1. Run `wrangler rollback --env production`.
2. Tell the on-call engineer in the `eng-oncall` channel.
```

Two things the facts do not settle, if you want them covered:

- **What "the output" is.** Step 2 says to check it is under 4 MB, but not which artefact or directory to measure, or what command to measure it with.
- **What happens after a rollback.** The runbook ends at notifying on-call. Whether the operator waits, retries, or hands over is unstated.
