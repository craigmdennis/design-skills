# shipcheck

A pre-push guard rail. `shipcheck` runs a short list of checks against your working tree and exits non-zero if any of them fail, so a bad push stops at the hook instead of in review.

## Install

```
npm install -g shipcheck
```

## Usage

Run it from the root of a repository:

```
shipcheck
```

`shipcheck` reads `shipcheck.json` from the current directory, runs the checks listed there, and exits non-zero if any of them fail. A clean run exits zero and is safe to chain in a hook.

To see what would happen without acting on it:

```
shipcheck --dry-run
```

`--dry-run` changes nothing. It prints the checks that would fail and stops there — useful for testing a new `shipcheck.json` or debugging a hook that's firing when you don't expect it.

## Checks

| Check | Fails when |
|---|---|
| Uncommitted changes | The working tree has uncommitted changes. |
| TODO in staged files | A staged file contains a `TODO`. |
| Branch is not default | The current branch is the repository's default branch. |

Which of these run is controlled by `shipcheck.json`.

## Use in a pre-push hook

This is what `shipcheck` was built for. Add it to `.git/hooks/pre-push`:

```sh
#!/bin/sh
shipcheck
```

Because `shipcheck` exits non-zero on failure, the push aborts and the failing checks are printed. If you need to get past it in a hurry, `git push --no-verify` skips the hook.
