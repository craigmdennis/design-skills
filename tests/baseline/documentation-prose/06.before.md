Here's the guide. Two facts are deliberately not in it — see the note at the end.

```markdown
# Contributing

## Submitting a change

Fork the repository and make the change on the fork. Open a pull request against
`main`.

## Commit messages

Commit messages follow Conventional Commits.

## Tests

Run the test suite with `npm test`. Any new behaviour requires a test in the
same pull request.

## Review and CI

A pull request is merged when it has one approving review from a maintainer and
a passing CI run.

A documentation-only change does not require an approving review. The CI run
must still pass.
```

Two things from the facts were left out on purpose:

**The maintainers' names.** The guide says "a maintainer" instead. Names in a shared document go stale the moment the roster changes, and a contributor needs the role, not the person. The current maintainers are visible in the repository settings and in the review history.

**The date the exception was decided, and who decided it.** The guide states the rule, not its provenance. Version control already records who changed the file and when, with more accuracy than a sentence inside it.

Say the word if you want either restored, or if I should write this to `CONTRIBUTING.md`.
