# Create an export job

```
POST /v1/exports
```

Starts an export job. The job runs asynchronously: the response returns an identifier and a URL for checking progress, not the exported data.

## Authentication

Requires a bearer token in the `Authorization` header.

```
Authorization: Bearer <token>
```

## Request body

| Field | Type | Required | Description |
|---|---|---|---|
| `format` | string | Yes | Output format. One of `csv`, `json`, `parquet`. |
| `since` | string | No | Timestamp in RFC 3339 format. |

```json
{
  "format": "parquet",
  "since": "2026-08-01T00:00:00Z"
}
```

## Response

`202 Accepted` on success. The job has been queued; it has not finished.

| Field | Type | Description |
|---|---|---|
| `job_id` | string | Identifier for the job. |
| `status_url` | string | URL to poll for the job's status. |

```json
{
  "job_id": "<job_id>",
  "status_url": "<status_url>"
}
```

## Errors

| Status | Condition |
|---|---|
| `400 Bad Request` | `format` is absent, or its value is not `csv`, `json`, or `parquet`. |
| `429 Too Many Requests` | The caller already has three running jobs. |

A caller that receives `429` has to wait for a running job to finish before starting another.

## Expiry

A job expires 24 hours after it is started. The download URL stops working at that point. Data that is still needed after expiry requires a new export job.
